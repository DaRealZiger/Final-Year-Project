Proposal 3: IoT Intrusion Detection System Gateway

Idea: Raspberry Pi sits between IoT devices and router, sniffs
traffic, detects attacks (rule-based + ML: Random Forest /
Isolation Forest), auto-blocks via iptables, shows alerts on a
web dashboard

[Claude yang bagi aq idea dan dia sendiri suka idea dia so...]
This one is the most "normal" scope of the three - clear
hardware (just a Pi), clear software stack, demoable live

Issues to raise:
- needs a labeled attack dataset to train the ML models on,
  where is that coming from? (public datasets exist but may not
  match real home IoT traffic)
- claims specific targets (<50ms/packet, <60% CPU) - need to
  actually benchmark this, not just assume it works
- running inline packet inspection + ML inference on a Pi 4 in
  real time is optimistic, may need to cut scope (e.g. sample
  packets instead of inspecting all)

Issue bincang:
Hardware bottleneck = Nak run ML model dkt raspberry Pi
Optimize latency    = Nak run ML model dkt raspberry Pi
Testing             = Pi akan jadi WiFi IoT, kite connect pakai laptop lepas
                      pakai software jgk, simulate perangai malicious activity
                      yang di label (tapi disorok label dari Pi)

                      Pi akan detect malicious activity dan labelkan
                      Pastu cross-check label dia dan jawapan kita (label)
Harga               = Mahal dan kecik, senang rosak, (RM 300 - 900)
                      Rosak dari short-circuit, kurang confiden
                      Nopal software boleh, hardware susah

Ask: does anyone have networking/Linux/embedded experience? Who

(Linux aq ade, embedded x jadi raspberry pi guna linux carry)
(ESP32, guna RTOS atau SDK x pernah)
